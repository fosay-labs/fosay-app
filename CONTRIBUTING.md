# Contributing to fosay-app

Thanks for helping. This repo holds the code that signs for an AI agent, pays its fees and
shows its owner what a passkey is about to approve. Changes there are reviewed for safety first.

## Before you start

1. Read the README's architecture section and, for anything touching contracts, the spec in
   [`fosay-contract/docs/SPEC.md`](https://github.com/fosay-labs/fosay-contract/blob/main/docs/SPEC.md).
2. Comment on the issue to claim it ("I'll take this"). One open claim per person. If there is
   no activity for 7 days, the issue goes back to the pool. Post a draft PR when you are stuck.
3. These paths are **security-sensitive**. Agree on the approach on the issue before coding:
   `packages/sdk/src/auth.ts` (agent signing allowlist), `apps/api/src/relayer/` (fee-paying
   guard), `apps/web/src/lib/decode-auth.ts` (what the owner sees before approving),
   `packages/agent/src/keys.ts` (agent key file).

## Setup

Node ≥ 22.12 and pnpm 10 (`corepack enable`). Postgres 16 only for running the API locally;
tests use in-process PGlite.

```bash
pnpm install
```

To run the API and web app locally, follow the README's quick start. To deploy, see
[`docs/HOSTING.md`](docs/HOSTING.md).

## Checks (the same as CI)

```bash
pnpm lint && pnpm typecheck && pnpm test && pnpm build
```

Run them and paste the real output in your PR.

## Rules for changes

- **Tests.** Every behaviour change comes with a test. API tests use real testnet events and
  transaction envelopes in `apps/api/src/__tests__/fixtures/`. Don't hand-edit them to make a
  case pass. Never skip a test or loosen an assertion.
- **Secrets.** Never log, return or put a secret in an error. The agent key stays on the agent's
  machine; the API never receives it. `NEXT_PUBLIC_*` variables are public.
- **Allowlists stay closed.** The agent signer and the relayer guard refuse anything not listed.
  Adding a call to either needs a test showing what is allowed and what is still refused.
- **Contract bindings** in `packages/sdk/src/generated/` are generated by
  `pnpm gen:bindings`. Don't edit them by hand.
- **Dependencies.** `@stellar/stellar-sdk` is pinned to one version across the workspace.
  Discuss new dependencies on the issue first.
- **Style.** ESLint and Prettier (`pnpm format`). TypeScript strict; no `any` without a comment.

## Pull requests

- Branch from `main`: `feat/…`, `fix/…`, `test/…`, `docs/…`, `chore/…`.
- [Conventional Commits](https://www.conventionalcommits.org/) subjects with the workspace as
  scope, for example `fix(web): show the decoded recipient in full`.
- One logical change per PR. Fill in the PR template. CI must be green and a maintainer must
  approve; `main` is protected.
- Update [`CHANGELOG.md`](CHANGELOG.md) under **Unreleased** for anything user-visible.
